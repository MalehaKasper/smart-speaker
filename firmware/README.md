# 🔊 Smart Speaker 2.1 — прошивка ESP32

**Мікропрограма центрального менеджера колонки (PlatformIO, C++, ESP-WROOM-32).**

Приймає аудіопотік по Bluetooth (A2DP Sink) і транслює його по I2S на DSP ADAU1401. Паралельно тримає BLE GATT-сервер для мобільного додатка ([`../app/`](../app/README.md)) — прийом гучності/джерела/коефіцієнтів EQ, відправка сповіщень про фізичний енкодер. Керує DSP по I2C виключно через Safeload-регістри (без клацань), обробляє роторний енкодер і ІЧ-пульт, виводить стан на екран TM1650, підсвічує бурштиновий VU-метр гучності на WS2812B. Налаштування зберігаються в NVS. Повна історія рішень — у [`../openspec/changes/`](../openspec/changes/).

### ⚡ Апаратні вимоги (не код — важливо не забути при монтажі)

- **WS2812B — рівень сигналу**: DIN стрічки очікує ≥3.5V (0.7×5V), а ESP32 GPIO видає 3.3V. Пряме підключення — поза специфікацією й ненадійне на довшому дроті. Потрібен level shifter (напр. **74AHCT125**) між `PIN_LED_STRIP` і DIN стрічки.
- **PAM8403 — розв'язка живлення**: підсилювач класу D чутливий до перешкод від перемикання струму WS2812B. Якщо обидва живляться від одного 5V-рейла без розв'язки, блимання стрічки буде чутно в динаміках. Потрібен конденсатор **1000+ мкФ** безпосередньо на клемах живлення PAM8403 і зіркова розводка живлення від спільного джерела (не послідовний ланцюжок через WS2812B).

## 🛠 Збірка

Потрібен [PlatformIO](https://platformio.org/) (CLI або VS Code розширення).

```bash
pio run              # збірка
pio run -t upload    # прошивка через USB (Type-C)
pio device monitor    # серійний монітор, 115200 baud
```

## 🧩 Архітектура

```
src/
├── main.cpp            Ініціалізація модулів, колбеки формують команди для черги
├── command_queue.cpp    Черга FreeRTOS + задача на Core 1 — єдине місце виконання I2C/LED/NVS
├── audio_input.cpp      A2DP Sink → I2S
├── ble_server.cpp        BLE GATT: control-характеристика (write), notify-характеристика
├── dsp_controller.cpp    I2C-майстер ADAU1401 (з очікуванням Selfboot), Safeload-запис гучності/джерела/EQ
├── inputs.cpp            Енкодер (переривання) + ІЧ (IRremote, RMT-бекенд)
├── display.cpp           TM1650 по I2C
├── led_strip.cpp         WS2812B VU-метр (FastLED, RMT-бекенд)
└── storage.cpp           NVS (Preferences): гучність, джерело, EQ
```

Жоден з BLE/енкодер/ІЧ-колбеків не звертається до I2C/LED/NVS напряму — вони лише кладуть команду в чергу (`command_queue.h`); задача на Core 1 обробляє чергу послідовно. Це ізолює час виконання радіостека (Core 0) від часу I2C/NVS-операцій.

Пінаут і константи — `include/config.h`.
