## Context

Додаток — розумний пульт і обчислювальний центр для рум-корекції колонки Smart Speaker 2.1. Він керує ESP32-прошивкою (`smart-speaker-firmware`) через BLE і самостійно виконує весь важкий DSP-розрахунок (FFT, побудова цільової кривої, коефіцієнти biquad) — прошивка на ESP32 лише застосовує вже готові байти через Safeload.

## Goals / Non-Goals

**Goals:**
- Миттєва (без відчутної затримки) відправка керуючих команд по BLE
- Коректний, перевірюваний розрахунок коефіцієнтів біквадратних фільтрів з ручних параметрів або з авто-рум-корекції
- UI, що завжди відображає актуальний стан з'єднання і синхронізується зі змінами, зробленими фізично на колонці (через notify)

**Non-Goals:**
- Будь-яка обробка аудіо на боці ESP32 — вся аналітика й розрахунок EQ виконуються в додатку
- Хмарна синхронізація пресетів між пристроями (лише локальне збереження)
- Підтримка кількох одночасно підключених колонок в MVP

## Decisions

- **`flutter_blue_plus` для BLE**: зрілий, широко використовуваний пакет з підтримкою Android/iOS, підписки на характеристики (потрібно для notify гучності) і стабільного API для write без відповіді (для миттєвості команд).
- **`record` для захоплення мікрофона + `fftea` для FFT**: `record` — кросплатформний захват PCM без залежності від нативного плагіна для конкретної фічі; `fftea` — чиста Dart-реалізація FFT, без нативних біндингів, що спрощує збірку на обох платформах.
- **Розрахунок biquad-коефіцієнтів — чистий Dart-код (без нативних бібліотек DSP)**: стандартні формули RBJ Audio EQ Cookbook добре документовані й досяжні без зовнішніх залежностей; спрощує тестованість (unit-тести на чистих функціях).
- **`shared_preferences` для локального збереження**: обсяг даних (кілька пресетів EQ + один MAC) невеликий, реляційна БД (Hive) є надлишковою.
- **Еквалайзер — 8 незалежних смуг, кожна оновлюється окремим BLE-пакетом**: узгоджено з `firmware/openspec/changes/build-firmware/design.md`. Додаток надсилає `0x03 [band_index: 0-7][b0][b1][b2][a1][a2]` (5 × float32, разом 21 байт) щоразу, коли користувач змінює одну смугу — не весь банк одразу. UI еквалайзера (`equalizer-screen`) оперує рівно 8 точками, не довільною кількістю.
- **Додаток надсилає float32, НЕ конвертує у фіксовану кому ADAU1401**: конвертація — відповідальність прошивки (вона вже інкапсулює все специфічне для DSP-чіпа). Додаток лишається незалежним від конкретної моделі DSP; калькулятор biquad-коефіцієнтів (`biquad-filter-calculator`) видає звичайні `double`/`float` за формулами RBJ, без знання про фіксовану кому.
- **MTU-негоціація — обов'язкова передумова для відправки EQ, не опція**: payload на смугу (21 байт) перевищує доступні 20 байт стандартного ATT_MTU=23 без негоціації. `ble-client-connection` мусить домогтись більшого MTU (`flutter_blue_plus` підтримує `requestMtu`) одразу після підключення і заблокувати відправку `0x03`, якщо це не вдалось.

## Risks / Trade-offs

- [FFT-аналіз через мікрофон смартфона чутливий до якості мікрофона й фонового шуму] → Використовувати kалібрувальний sweep-сигнал з достатньою амплітудою і, за можливості, усереднення кількох проходів перед побудовою цільової кривої.
- [BLE MTU за замовчуванням (23) на 1 байт менший за потрібний для payload EQ (21 байт корисних даних, 20 доступно без негоціації)] → Викликати `requestMtu` одразу після підключення; якщо досягнутий MTU < 24 байти, блокувати відправку EQ і показати користувачу помилку замість мовчазного збою.
- [Втрата BLE-з'єднання під час відправки однієї смуги EQ може залишити прошивку з частково оновленим банком] → Кожна смуга оновлюється власним атомарним Safeload на боці прошивки (`firmware/`), тому втрата зв'язку зачіпає щонайбільше одну смугу; додаток має показувати статус "надсилання" і повторювати саме ту смугу при розриві.
